# Quick start (CPAT-AI-Mitigation-Prototype v7.1)

## What it is

The mitigation module of CPAT (the IMF/World Bank Climate Policy Assessment Tool), rebuilt as one readable Excel workbook for one country at a time. Nothing in the formulas is country specific: every country number comes from the reference tables (data sheets), looked up by the country code on `Settings` (C4). The shipped data are complete for Egypt. Policies (carbon tax, new ETS, feebates, fuel price reform, methane fee, existing carbon pricing) change retail energy prices. Prices change fuel use in 16 subsectors and 8 fuels, and a power model turns electricity demand into dispatch, investment and electricity prices. The results run to 2041 in real 2026 US dollars: fuel use, revenues, CO2 (optionally calibrated to the inventory), other GHGs, local air pollutants and GDP effects. Every formula is at most 100 characters and one formula serves a whole block. An independent Python recomputation checks every number.

## In 15 minutes

1. **Open** `CPAT-AI-Mitigation-Prototype-v7.1.xlsm` in Excel 365 (also at the repository root). Unblock the file if it was downloaded and enable macros. It opens on `ScenarioCompare`, the dashboard, **without recalculating**: the file ships with its calculated values and in manual calculation. Click **Recalculate now** after any change (it reports the seconds taken), or **Recalculation on/off** to switch automatic calculation on (Excel applies the mode to every open workbook). Older Excel calculates 2022-2040; only the live scenario's LAMBDA cells show errors.
2. **Test once:** in the VBA editor (Alt+F11) run Debug > Compile VBAProject: it must report nothing (the cloud tests the macros in LibreOffice, which does not compile them as Excel does). Then on `ScenarioCompare` click **First-run test** (grey buttons; or Alt+F8, `CheckBatchRun`). The MacroCheck table (tab `Check, Variables, Lambdas`) must show PASS.
3. **Read the results:** `ScenarioCompare` (front tabs: `Cover`, `ScenarioCompare`, `ScenarioDefinition`). Choose **Results from** Stored (`StoredOutputs`, every stored scenario) or Live (`LiveOutputs`, the scenario groups of Mitigation), the year, then Recalculate now. The key table shows energy CO2, GHGs, revenue, the GDP effect and net welfare against the baseline (level, difference, % difference); a bar chart compares CO2; four time-series tables have their chart beside them, and the title of each is a dropdown of the indicators. Only scenarios with results appear in the charts. `Mitigation` has two scenario groups: 1 = baseline (plain formulas), 2 = the live policy scenario (named LAMBDAs); more by copy-paste of group 2.
4. **Change a policy:** on `ScenarioDefinition`, column K is the live scenario. Change, for example, `CPLevelTarget` (carbon price in the target year); scenario 2 recalculates.
5. **Power policies and settings:** every power input on ScenarioDefinition (rows 242, 262, 342-415 and 482) is read in each scenario's own column, e.g. no new coal (`NewInvCoa` = No), nuclear from 2030 (`NewInvNuc` = Yes, `NewInvNucYear`), PPAs (`PPAProportionCoalGas`, rows 382-386), renewable subsidies (rows 354-357 and 482), rebating power revenues (`PowerRebates`), the electricity excise (`ScenarioSelected` = Electricity excise; manual excise on `Manual inputs` rows 161-162 with `AdditionalExcise` = Yes). Technical inputs (WACC, capacity factors, storage, logit constants) can differ by scenario too, but scenario 1 stays the baseline of every scenario. The final investment deficit to gas is a global switch (`Settings` C45).
6. **Road transport:** set `TrModel` on ScenarioDefinition (row 340) to Engineer to use the engineer road model of section 5b (vehicles, cost of ownership, EV choice) instead of the elasticity approach; its policies (feebates, distance tax, EV subsidies, purchase taxes, charging subsidies) are ScenarioDefinition rows 418-479.
7. **Inputs outside ScenarioDefinition:** tab `Manual inputs` is the legacy tab of that name at its legacy addresses (paste the legacy tab from row 3). The note on each block's title row says what reads it. The prototype reads: the ETS goal-seek settings (E10:E12), the price controls by fuel and sector when GovPriceControls = Manual (J167:J180), the methane fee scope by source (J196:J200), the manual international prices when IntEnerPricForeSource = Manual (rows 220-225), the manual fiscal multipliers (J261:U268), the non-energy GHG elasticities (K326:M327), the new electricity excise (J161:AF162, with AdditionalExcise) and the fuel economy of new BEVs of the engineer road model (rows 374-377). The other blocks are there, not read: features not built yet.
8. **Run many scenarios:** copy the last definition on `ScenarioDefinition` (column N) one column right, give it a short name (row 2: the legend in the charts), edit it, set row 4 Run? = Yes, click **Run stored scenarios** on `ScenarioCompare`. Results go to `StoredOutputs` (sorted: like variables together; every lookup finds rows by output code, so any order works); the dashboard shows up to 10 scenarios; blank scenario columns of ScenarioDefinition are grouped and collapsed.
9. **Linked data tables:** choose the data source on `ScenarioCompare` (Embedded = the shipped data; Dummy - local file = `data/workbooks/CPAT_Data_dummy_python.xlsx`; Dummy - SharePoint) and click **Update data tables**; the status is at the top of `Cover`. Nine tabs are linked (v7.1): Balances, EnergyCons, Prices_dom, HHSurvey, IO_GTAP and HH_Elast take the rows of the country (Settings C4); WEO, GDPRatios and UNPop take every row (other countries and regions are used). Each table is copied by column name, so the column order of the data workbook does not matter; the tab keeps its header row and formula columns; prototype columns missing in the table are reported, and with no rows the shipped data stay. The dummy data are fake values: use them to test the links, not for results.

## Another country

Set `Settings` C4 to its ISO code. The data tabs are the legacy tabs, and all but the proprietary ones already hold every country: power technology data (`Power`), cost of capital (`CoC`), GHG inventory and emission shocks (`GHGs`), countries and regions, existing carbon pricing (`ECP`), methane inputs, population, household shares of oil products (`OilProductShares`, v4.12), international prices (`Prices_int`), domestic prices (`Prices_dom`, 220 countries), elasticities, ETS semi-elasticities (`ETS+LTS`), GDP and deflators (`WEO`), CO2 emission factors (`EF_GHG`: country, else region, else world, as legacy), SCC, household elasticities, GDP ratios, road transport data, multipliers. What legacy Mitigation selects from them for the country (its elasticities, multipliers, WEO series, prices, carbon pricing, emission factors and power data) is computed on the `Inputs` tab by formula, so it follows C4. The proprietary legacy tables hold Egypt only here; they are the legacy tables unchanged, so paste the full legacy data rows at A4: `Balances`, `EnergyCons`, `EF_PM`, `IO_GTAP`, `HHSurvey`, `ASPIRE`, `WHOCooking`. Tabs kept at legacy addresses (`Countries`, `Elasticities`, `ETS+LTS`, `Multipliers`, `Prices_int`, `ECP`, `Transport3`, `Power`, `CoC`, `GHGs`) take the legacy tab pasted from row 3. The baseline CO2 by ETS sector (`BaselineCO2`, behind the CO2 calibration, on as legacy since v4.11) is scenario-1 output stored as values: rebuild with `COUNTRY` in `build_v7_1.py`, or paste the country's scenario-1 values under its key. Tab by tab: `DataTabs.md`. A missing row shows as #N/A, never as another country's number.
