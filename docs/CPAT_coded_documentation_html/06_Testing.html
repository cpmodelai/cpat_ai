6  Testing

In short

  • Run pytest from coded/ before every commit (about one minute). Everything must pass.
  • The main test is the comparison with Excel-AI: every output code of every built block, for Egypt’s scenarios 1 and 2, every year 2022-2041, must equal Excel-AI’s stored value within 1e-9 (relative where the value is above 1). The distribution sheet is compared the same way, basket and deciles.
  • Known differences are the codes where Coded CPAT fixes an Excel-AI bug that is still open in the prototype; the tests leave them out of the match and check that they do differ (Appendix F).
  • The status below is generated: python make_qmd.py --tests (in docs/CPAT_coded_documentation_qmd/) runs the tests and rewrites it.

The tests

Test file What it checks
test_mitigation.py Every mitigation block against Excel-AI’s stored values, scenarios 1 and 2 (one test per block, chapter 8); the known differences
test_distribution_incidence.py The Distribution sheet by section, scenario groups 1 and 2; the known differences
test_data_steps.py The data steps (what Excel-AI computes on its Inputs sheet: prices, power, elasticities, emission factors)
test_foundations.py Index sets, the variable registry, inputs, the run loop
test_compare.py The comparison harness itself (codes, years, tolerance)
test_equation_ids.py Every equation id cited in the code exists in the equation list
test_speed.py A cached two-scenario run is under 2 s and equal to a fresh run
test_run_model.py The command line writes the result files
test_shiny_app.py The app imports; its scenarios become a scenario set; its tables and graphs have data

When to run what

When Run
Any change to the code pytest (from coded/)
A change to one block pytest cpat_testing/test_mitigation.py -k "<block name>" first, then everything
Data changed cd data && pytest tests, then pytest in coded/
Excel-AI has a new version Re-extract the reference values (below), then pytest
Before a release Everything, plus python run_model.py and shiny run app.py by hand

The comparison with Excel-AI

The reference values are Excel-AI’s stored values, extracted from the workbooks into CSV files:

python cpat_testing/compare/extract_excel_ai.py                  # mitigation: reference/excel_ai_<version>.csv
python cpat_testing/compare/extract_excel_ai.py --distribution   # reference/excel_ai_distribution_<version>.csv

cpat_testing/compare/compare.py compares a results table with them code by code and year by year and reports the first year that differs. For a quick look while working:

from cpat_testing.compare.compare import compare, reference, summary
report = compare(results.by_code('EGY'), ref=reference())
summary(report[report.first_bad.notna()])

Known differences

cpat_testing/compare/known_differences.py lists, by Excel-AI bug, the codes where Python differs on purpose. When Excel-AI ships the fix of a bug, delete its entry: the codes must then match again. A test fails if a listed code matches Excel-AI (the entry is out of date) or if an unlisted code differs.
