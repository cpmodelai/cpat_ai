The CPAT-AI Project

Rebuilding and extending the Climate Policy Assessment Tool, in Excel and in Python

Overview

The Climate Policy Assessment Tool (CPAT), developed jointly by the World Bank and the IMF, models the fiscal, economic, energy, environmental and distributional effects of carbon pricing and related climate policies for more than 180 countries. Its methodology is set out in full in the CPAT Documentation tab.

CPAT-AI is the workspace in which that model is being replicated, checked and extended. The legacy CPAT workbook is the reference: every formula of the new models is traced back to it, every difference from it is recorded, and every legacy bug found on the way is documented with a cell-level fix plan that the CPAT team can apply to legacy CPAT itself.

Two projects

Excel-AI

Excel prototypes that replicate legacy CPAT module by module, built from Python scripts so that every workbook can be regenerated, checked and versioned. Folder excel_ai/.

Coded CPAT

A component-based Python reimplementation of the model, with a Shiny app. Validated Excel prototypes are ported here once checked. Folder coded/.

Both projects share the same inputs and codes: legacy MTInputs rows and NameOfParameter names, and identical input and output codes in Excel and in Python. Both read their data from the single root folder data/.

Bugs and issues

The rule

Never replicate a legacy bug; always replicate a legacy issue, and track it.

KindMeaningWhat the prototype does
Bug (L, M)Legacy does not compute what it means to: a wrong row, a double application, a dead reference.Fixes it; the fix is written up as a cell plan for legacy.
Issue (I)Legacy does what it means to, but the choice is open to question.Does the same and tracks it.
Data problemAn issue in the data rather than the formulas.Replicated; ranked Very high where a legacy bug with a cell plan covers it, Extremely high where the prototype must align with legacy.
Departure (LD)A deliberate difference that is not a bug fix.Kept only by user decision, and tracked.
Upgrade (U)A new feature beyond legacy.Tracked.

The register behind these lists is a single source (excel_ai/mitigation/register.py) from which the bug book, the tracker and the short lists are generated. At register v8.5 it held 168 legacy bugs and 14 prototype bugs, and 82 issues (12 of them data problems), 40 departures and 9 upgrades.

Excel-AI

The Excel prototypes are written with openpyxl and recalculated in LibreOffice, so they build and check on Linux and in cloud sessions; Excel 365 is used only for review. Each module has a builder, a quick check run after every change and a full check run at milestones.

Modules

ModuleWhat it doesSources
MitigationThe integrated prototype: prices, power, transport, emissions, ETS, macro and results, with the distribution tab. Runs scenarios in batch through VBA.excel_ai/mitigation/
DistributionHousehold effects by decile of a mitigation scenario. Cut from the built mitigation prototype, so there is one copy of its formulas; reads Mitigation through a single tab, FromMitigation.excel_ai/distribution/
Air pollutionStandalone rebuild of the legacy Air Pollution module: from pollutant emissions to concentrations, exposure, health burden and economic outputs.excel_ai/air_pollution/

The current version of each main file sits at the top of excel_ai/ as <Name>_v<version>; older versions are in releases/, and permalink/ holds the _latest copies that other workbooks link to.

Building and checking the mitigation prototype

cd excel_ai/mitigation
python build.py                # the prototype, about 8 minutes
python check_quick.py          # after every change, about 2 minutes
python check_full.py           # at a milestone
python make_documentation.py   # bug book, tracker, codes map, Word documentation, BUGS.md, ISSUES.md

Coded CPAT

The Python model runs the mitigation module and the household distribution module, from run_model.py or from the Shiny app. Its input keys are the legacy NameOfParameter names, in legacy units, so a scenario means the same thing in Excel and in Python.

PathContents
cpat_model/mitigation/Mitigation module components
cpat_model/distribution/Household incidence by decile, revenue recycling, welfare
cpat_shiny/, app.pyThe Shiny application
cpat_testing/pytest suite mirroring cpat_model/
 
cd coded
pip install -r requirements.txt -r dev-requirements.txt   # Python 3.12
python run_model.py
pytest
shiny run app.py

Data

All data live in the root folder data/, with the scripts that convert them; nothing is copied into the project folders. Only dummy or public data are committed: the real, proprietary tables stay outside the repository.

FolderContents
dummy/The Coded CPAT inputs, with fake values in the real formats
workbooks/The data workbook in Python format and in CPAT (legacy) format
legacy_dummy/The four proprietary tables in the legacy layout, dummy version, to paste into legacy CPAT
mvp_legacy_extracts/The legacy tables the mitigation prototype is built from
distribution/, air_pollution/Module data pipelines and public reference tables
scripts/, tests/Conversion scripts and their tests
