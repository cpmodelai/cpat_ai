4  Data and working practice

The data the models read, the norms the project works under, and where everything is in the repository.

4.1 Data

All data of the project live in the root folder data/ (rebuilt 2026-10-30). The tidy tables are the source of truth; the legacy-compatible workbook is written from them. Code reads the data from there by a path relative to the repository; nothing is copied into the project folders.

NoteSix proprietary tables

Balances, EnergyCons, Prices_dom, IO_GTAP, HHSurvey and Tran_Scatter are proprietary; every other table is non-proprietary. Their full versions stay outside the repository, on the restricted team site, and are read through FULL_DATA_PATH. The repository holds the public data and the Egypt rows of the proprietary tables perturbed within ±3%, identities kept (edition Public01).

4.1.1 Layout

The data are organised in editions (data/editions.csv): data/Public01/ is the public one (proprietary tables perturbed), Full01 (real) lives in a private repository. Every edition has the same structure.

Item What it holds Read by

Public01/legacy_xlsx/CPAT_LegacyData.xlsx The same data in the legacy layout, so a block pastes onto legacy CPAT People adjusting legacy CPAT; Excel-AI

4.1.2 Scripts

python data/scripts/tidy_convert.py to-xlsx --tidy data/Public01/tidy --out data/Public01/legacy_xlsx/CPAT_LegacyData.xlsx
python data/scripts/build_catalog.py

When a tidy table changes, rewrite the workbook in the same task and run the tests. Details: data/README.md.

4.2 Working in the repository

The project works under written norms (excel_ai/core/NORMS.md). They bind people and AI agents alike; AGENTS.md at the root of the repository routes any AI agent to them. This section summarises the norms that shape the files a reader meets; NORMS.md is the authority.

4.2.1 Files, versions and releases

Where the files are. People open the workbooks in excel_ai/active_workbooks/ (<Name>_latest, the permalinked copies the modules link to). Every version of a module workbook, the current one included, is in the module’s releases/ folder as <Name>_v<version>.<ext> (for example excel_ai/mitigation/releases/CPAT-AI-Mitigation-Prototype_v1.1.0.xlsm). The documents:

File Where What it is
Legacy_CPAT_Bugs_v<version>.docx excel_ai/bugs_and_legacy/ The legacy bugs, with every cell-level fix plan
Tracking_Legacy_Bugs_v<version>.xlsx excel_ai/bugs_and_legacy/ The master list of bugs and issues
CPAT-AI_CodesMap_v<version>.xlsx docs/ The code protocol, vocabularies, variables, output codes and every input
CPAT-AI_Overview_v<version>.pptx excel_ai/ The slide deck: status, how to use it, results (latest copy: docs/presentations/01_CPAT-AI_Overview_latest.pptx)
BUGS.md, ISSUES.md, NORMS.md, TODO.md, CAVEATS.md excel_ai/core/ The bug and issue lists, the rules, the open work, the task log
  • Older versions of the documents move to excel_ai/bugs_and_legacy/register/releases/ (the deck’s to excel_ai/mitigation/releases/) when a new version is written (excel_ai/core/tools/release.py).
  • Version numbers. Three parts, 0.<major>.<minor>, until the first full release 1.0.0: the last part for fixes and small features, the middle part for structural or methodological change. Each module with its own builder (distribution, air pollution) has its own version and records which mitigation version it was built from. Files released before the change to three parts were renamed; their contents keep the old two-part numbers. The register documents, the tracker and the codes map carry the version of the mitigation prototype they were made with.
  • One version table per workbook and generated document, in the same columns: version, date, description (with register codes), and the largest regression difference against the previous release.

4.2.2 Checks

Check When What it does
Quick check (check_quick.py) After every change; a few minutes Structure, names, literals, formula length, a full recalculation with no error cells, the code protocol, the change of every output code against the last release
Paste test (check_paste.py) Every release Pastes the live scenario’s column group into further groups, as a user would, and checks that the pasted groups number themselves, show no errors and reproduce the stored results
Full check (check_full.py) At a milestone; several hours Everything, including the macro tests
Independent recomputation Within the checks Python reference models of the power, transport and distribution blocks reproduce the workbook’s numbers

Every increment is a regression test: the new version’s values are compared with the previous release, and every difference is zero or explained in the version table.

4.2.3 Excel written by code

The Excel prototypes are written with openpyxl and recalculated in LibreOffice, so they build and check on Linux and in cloud sessions. Excel 365 is used for review only. The norms set the column layout of every sheet type, a visual style guide (colours, fonts, borders, sections), formula rules (at most 100 characters; one formula serves a whole block), copy-paste ability of scenario columns, and lint rules that every file passes before it ships so Excel never shows a repair prompt.

4.2.4 Task completion

Every finished task ends with an entry at the bottom of excel_ai/core/CAVEATS.md, the single record of completed work: the task, its inputs, its outputs and its caveats. Earlier entries may be corrected but not deleted. Open work is listed in excel_ai/core/TODO.md and coded/TODO.md.

Norms follow the lessons. A mistake whose cause could recur ends with a norm and a check that would have caught it, added in the same task.

4.2.5 Methodology and version notes

A methodology describes the method as it is now, for a reader who has never seen an earlier version. Change history goes in separate version notes: the version tables and CAVEATS.md.

Each book has few chapters, each with many sections (user 2026-10-31): new material goes into a section of an existing chapter. The latest slide decks are in docs/presentations/ and linked at the top of each tab. Chapter 2 is generated from the documents beside the code by make_qmd.py; edit those sources, not the generated chapter. A change to the method of a block updates its chapter in the CPAT-AI Model book the same day (and the compact method note in excel_ai/mitigation/docs/methods/). GitHub builds and publishes the website on every push to main that changes the documentation (.github/workflows/pages.yml). To rebuild by hand:

cd docs/CPAT_ai_documentation_qmd
python make_qmd.py     # regenerate chapter 2 from excel_ai/mitigation/docs/
quarto render          # write ../CPAT_ai_documentation_html/
