1  Overview

1.1 What Excel-AI is

Excel-AI is the Excel side of the CPAT-AI project: Excel prototypes of legacy CPAT, written by Python builders (openpyxl) and checked by LibreOffice recalculation and independent Python recomputation, for modellers and reviewers who work in Excel and for the CPAT team. Its files are in excel_ai/.

  • Modules. The mitigation prototype (the integrated model, with the distribution tab), the standalone distribution module and the standalone air-pollution module.
  • Inputs. The policy and parameter inputs are the rows and names of the legacy MTInputs sheet (NameOfParameter), in legacy units. The codes map (docs/CPAT-AI_CodesMap_v<version>.xlsx, tab Inputs) lists every input with its row, its name, its legacy name and its Python key.
  • Codes and data. Input codes, output codes and the sector and fuel vocabularies are shared with the Python model (the CPAT Python tab), which replicates Excel-AI number for number. Both read the root folder data/ (Section 5.1).
  • The rule on bugs and issues (Section 1.5).

1.2 Legacy CPAT: the reference

The legacy workbook is the ground truth for both models. The latest version, 1.0pre_465, is kept read-only in data/ (the earlier NoPropData copies of 456, 459 and 465 are no longer in the repository):

File Role
data/legacy/CPAT 1.0pre_465_Shell.xlsb The legacy CPAT workbook with its six proprietary tabs empty (every other tab filled); the reference for input rows and names, and for the register’s cell references
data/Public01/legacy/CPAT 1.0pre_465_Public01.xlsb The shell filled with data edition Public01’s tables (the proprietary ones perturbed)

The legacy workbook is never edited or re-saved; work is done on copies in scratch folders.

1.3 How the work proceeds

  1. Replicate. A block of legacy CPAT is rebuilt in the prototype, formula by formula, with the same sections and the same codes.
  2. Check. An independent Python recomputation of the block reproduces every number; the prototype’s result is compared with legacy’s stored results.
  3. Classify every difference. A difference is either a legacy bug (fixed in the prototype, with a cell-level fix plan for legacy), a legacy issue (replicated and tracked), or a departure decided by the team (tracked).
  4. Release. The builder writes a new version; the quick check, the paste test and the regression against the previous release must pass; the register documents, the tracker, the codes map and the deck are regenerated.
  5. Port. Validated blocks are ported to the Python model (the CPAT Python tab).

1.5 Bugs and issues

ImportantThe rule

Never replicate a legacy bug; always replicate a legacy issue, and track it.

The rule applies to every model of the project, in Excel and in Python. It keeps the prototypes faithful to legacy CPAT where legacy does what it means to, and correct where it does not, and it makes every difference from legacy visible.

1.5.1 Definitions

Kind Code Meaning What the prototype does
Legacy bug L Legacy does not compute what it means to: a wrong row, a double application, a dead reference Fixes it, never replicates it; the fix is written up as a cell-level plan for legacy
Prototype bug M A bug found in the prototype itself Fixes it and records it
Issue I Legacy does what it means to, but the choice is open to question Does the same as legacy and tracks it
Departure LD A deliberate difference from legacy that is not a bug fix Kept only by decision of the team; tracked in the prototype’s LegacyDiff sheet
Upgrade U A feature beyond legacy Tracked

Data problems are issues. They are replicated. Where legacy needs a formula fix to handle the data correctly, that fix is a legacy bug (L) with a cell plan and the issue is ranked Very high; where no cell plan is possible, the prototype aligns with legacy exactly and the issue is ranked Extremely high.

1.5.2 The register

Every bug and issue lives in one register, the single source from which the documents are generated:

Document What it holds
excel_ai/bugs_and_legacy/Legacy_CPAT_Bugs_v<version>.docx The legacy bugs, each with its cell-level fix plan, and the data problems by priority
excel_ai/bugs_and_legacy/Tracking_Legacy_Bugs_v<version>.xlsx The master list of bugs and issues, every module, in the same columns; shared with the CPAT team
excel_ai/core/BUGS.md, excel_ai/core/ISSUES.md The two short lists
excel_ai/bugs_and_legacy/register/Legacy_CPAT_Register.json The register as data

The register is written in excel_ai/bugs_and_legacy/register/issues_register.py and register.py; make_documentation.py regenerates every document from it at each release.

1.5.3 Current counts

  • 231 legacy bugs, 22 prototype bugs, 20 documentation bugs. Legacy 465: 52 fixed (confirmed), 9 fixed with caveats, 2 marked fixed but not fixed, 168 open. (register v1.1.0, excel_ai/core/BUGS.md)
  • 135 issues (14 data problems), 35 departures (LegacyDiff), 14 upgrades. (register v1.1.0, excel_ai/core/ISSUES.md)

The status Legacy 465 records whether the CPAT team has fixed each bug in the latest legacy workbook; each claimed fix is checked against the workbook (excel_ai/bugs_and_legacy/fixes/check465/).

1.5.4 Priorities

Issues and data problems are ranked so the most urgent are seen first: Extremely high and Very high for data problems (as defined above), then Major and Minor. Bugs carry High, Medium or Low by their effect on results.
